# VibeCagOS — Repository Audit

> **Purpose.** This is the Section 0 audit requested by the master plan: the
> actual state of the tree read from source, mapped against the master plan's
> milestones, with a gap list and a proposed adjusted plan. It is a *point-in-
> time* document (2026-10-08, commit `084554a`, version 0.6.0).
>
> It supersedes the "known state" in the master plan: **the shell already runs
> in Ring 3, the timer, syscalls and preemptive scheduler are functional and
> covered by automated tests.** That premise is out of date.
>
> Companion documents already in `docs/`: `ARCHITECTURE_AUDIT.md` (defect
> tracker), `RING3.md`, `FILESYSTEM.md`, `VBIN.md`, `SYSCALL_ABI.md`,
> `USERSPACE.md`, `REGRESSION_MATRIX.md`, `FINAL_STATUS.md`, `ROADMAP.md`,
> `BASELINE.md`.

## 1. Target architecture and toolchain

| Item | Value |
|---|---|
| Architecture | **x86 (i386), 32-bit protected mode**, no PAE, no long mode |
| Compiler | `clang` (`-m32`), assembler `clang`, linker `lld` |
| C standard | C11, freestanding (`-ffreestanding -nostdlib`), no libc |
| Host/tooling | WSL2 Ubuntu (Linux); also builds on native Linux |
| Emulator | `qemu-system-i386` |
| Build flags | `-std=c11 -O2 -g3 -Wall -Wextra -m32 -fuse-ld=lld -fno-stack-protector -ffreestanding -nostdlib -fno-pie -no-pie` |

The architecture is coherent and sound; **nothing here is fundamentally
broken**, so per ground rule 1 the target and toolchain are kept.

Flags gap: the build uses `-Wall -Wextra` but **not `-Werror`**, and there is no
`-MMD -MP` dependency tracking. Both are Milestone 0 items.

## 2. Boot method

- **GRUB (Multiboot v1)**. The Multiboot header is placed in `src/kernel/boot.s`
  (`KEEP(*(.multiboot))` in `src/kernel/kernel.ld`); GRUB loads `kernel.elf`
  and jumps to `_start`.
- `_start` sets up a temporary stack, saves the Multiboot info pointer, then
  calls `kernel_main`.
- GRUB config is generated by the Makefile (`isodir/boot/grub/grub.cfg`) and
  packed with `grub-mkrescue` into `os.iso`.
- **No disk bootloader** (GRUB only); the OS ships as a CD-ROM ISO plus a raw
  `disk.img` attached as an IDE drive.

`make clean` removes artifacts. There is **no** `lint`/`format` target yet.

> It is now 16 MiB and the Makefile creates/repairs it automatically.

## 5. Memory layout

**Kernel (per `src/kernel/kernel.h:37-53`, `kernel.ld`):**
```
0x00100000  kernel image load address (_start, identity mapped)
              .boot/.text/.rodata/.data/.bss
              + 128 KiB boot stack  -> __stack_top
              + 64 MiB free region  -> __free_ram_end
0x00000000 .. __free_ram_end   identity-mapped, supervisor-only,
                               page tables SHARED by every address space
0xC0000000 .. 0xFFFFFFFF       kernel-only: MMIO (NIC, LFB)
```

**User (per-process private mappings, PD slots >= 64):**
```
0x10000000 (USER_BASE)   user image: text RO at base, data/bss RW after
0x1FFFC000 .. 0x20000000 user stack, 4 pages, grows down
up to 0xC0000000         reserved for future heap/mmap
```

There is **no higher-half kernel mapping**: the kernel is low-identity-mapped.
This satisfies the master plan's "if not already" clause only loosely; a move to
higher-half is a large, risky refactor with little functional payoff for a
32-bit teaching OS — see decision **D3**.

The boot memory map **is** parsed (GRUB Multiboot memory map feeds
`pmm_init(mem_start, mem_end)`).

## 6. What runs where (privilege split)

Contrary to the master plan's premise, the split is already real and tested:

- **Ring 0 (kernel):** boot, GDT/IDT/TSS, PIC/PIT, keyboard, serial, VGA,
  ATA PIO + IDE, PCI, RTL8139 + net stack, paging/PMM/heap, VFS + VibeFS +
  procfs + devfs, process/scheduler core, syscall dispatcher, idle thread,
  `kinit` thread, klog. The GUI (`src/drivers/gui.c`) is a **Ring-0 demo** not
  reachable from the default user-shell boot path.
- **Ring 3 (user):** `/sbin/init` → `/bin/sh` → coreutils and `utest`. Loaded
  as **VBIN** images. CPL=3 is asserted by `test-ring3`; illegal instructions
  from Ring 3 kill only the process (`test-faults`).

Boot chain: `kernel_main` → `process_init` (idle pid 0) → `kinit` kthread
(pid 1) → spawns `/sbin/init` (pid 2) → `init` spawns `/bin/sh` (pid 3) →
shell. **`init` is pid 2, not pid 1** (decision **D-init**).

## 8. Test infrastructure (actual)

- `tests/run.sh <suite>`: boots QEMU headless (`-serial stdio -display none`),
  drives the **user shell** over a FIFO, waits for each prompt, then greps the
  captured log. 11 suites. Log kept at `/tmp/vibe-last.log` on failure.
- `tests/persist.sh`: boots **twice on one disk image**, writes a file in boot 1
  and reads it in boot 2 (proves persistence). This is the 12th suite.
- `utest.c` is a Ring-3 self-test battery (`utest <n>`), the main assertion
  vehicle.
- The suites are real and green: `make test-all` = **12/12**.

Gaps vs master plan §2.4/§2.5:
- **No `isa-debug-exit`** device / real process exit code; pass/fail is derived
  from grepping serial text, and `make test-all` stops at the first failing
  suite.
- **No kernel-space `KTEST` harness**; all tests are user-space programs driven
  by the shell.
- **No `tools/run_tests.sh`** unified runner with timeout/exit code.
- **No CI** (`.github/workflows` absent).

## 11. Decisions needed (real forks)

**D1 — Executable format.** The tree deliberately consolidated on **VBIN**
(custom, 28-byte header, RO/RW split, converted from an ELF build intermediate
by `tools/vbinpack.c`); the ELF loader was removed. The master plan's M3 says
"load **ELF** executables … embed programs in an **initrd** (tar/cpio)". These
conflict.
- *Keep VBIN* (recommended): already tested, simple, matches the RO/RW loader
  and `test-exec`. Record an ADR. Add initrd only as the delivery mechanism.
- *Adopt ELF*: rewrite the loader, re-introduce segment mapping and an initrd,
  lose the current tests' assumptions.

**D2 — Disk filesystem.** VibeFS exists, persists across reboots, and has
indirect blocks (~8 MiB files). The master plan's M6 asks for FAT32 or an
ext2-like FS with host `fsck` verification.
- *Keep VibeFS* (recommended): it works and is tested; add an ADR explaining the
  tradeoff (not host-inspectable, no fsck). Optionally add FAT32 later as a
  second FS to demonstrate the VFS.
- *Add FAT32*: large effort, real interoperability benefit.

**D3 — Kernel virtual base.** Master plan M2 suggests higher-half "if not
already". The kernel is low identity-mapped.
- *Keep low identity map* (recommended): correct and simple for i386/no-PAE;
  higher-half is high-risk with no functional payoff here.
- *Go higher-half*: broad, risky refactor (linker, paging, every address).

**D4 — Repository layout.** The master plan proposes `boot/`, `kernel/arch/`,
`mm/`, `lib/`, etc. Current layout is clean-ish but not arch-isolated.
- *Keep, minimal* (recommended): fix the concrete gaps; introduce `arch/` only
  when a second architecture is actually attempted.
- *Restructure now*: churn across every file with no behavior change.

**D5 — Warnings-as-errors.** Add `-Werror` now (recommended) and fix whatever
surfaces, before feature work.

**D-init — pid numbering.** `init` is pid 2 (pid 1 is the kernel `kinit`
thread). The master plan wants `init` as pid 1. Low risk to change; recommended
as part of the process-model milestone.

## 12. Proposed adjusted plan (small, verified steps)

Ordered by value and risk; each step ends green (`make`, `make test-all`),
documented, committed.

**Step 0 — Infrastructure (master plan M0)**
1. Adopt `-Werror`; add `-MMD -MP`; optional out-of-tree `build/`.
2. Add `isa-debug-exit` reporting so a suite run yields a real exit code;
   add `tools/run_tests.sh` with timeout, keep serial assertions.
3. Add `docs/ARCHITECTURE.md`, `MEMORY_MAP.md`, `SYSCALLS.md`, `DECISIONS.md`,
   `TESTING.md`, `CONTRIBUTING.md`, `.clang-format`, `.editorconfig`; fix the
   README quick-start.
4. Add GitHub Actions CI (build + `make test-all`, artifact on failure).
5. `panic()`: add control-register dump + frame-pointer backtrace; add
   `ASSERT()`; add `irq_register()`.

**Step 1 — Process model completion (M3/M4/M7)**
`vmm_clone_address_space` + `fork()` + leak test → init as pid 1 + reaper →
`dup`/`dup2` → signals + Ctrl+C → TTY line discipline → libc-lite `malloc`
(over `brk`) and `printf`.

**Step 2 — Storage (M6)**
ramfs/tmpfs + initrd for boot programs → block cache with write-back/`sync` →
(decision D2) FAT32 or VibeFS ADR + MBR parsing.

**Step 3 — Scheduler (M5)**
`sched_ops`, priority/MLFQ + aging, per-process CPU/ctx-switch stats in `ps`.

**Step 4 — Hardening (M8)**
Syscall fuzzer test → stack canaries + guard page → `BENCHMARKS.md`.

Each of these becomes its own commit(s). Steps 1–4 are re-ordered relative to
the master plan so that preemption/process/init work (the highest-value gaps)
lands before filesystem niceties.
